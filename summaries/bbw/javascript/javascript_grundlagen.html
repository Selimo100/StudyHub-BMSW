LU01 — Einführung in JavaScript

Bevor du eine Zeile Code schreibst: was ist JavaScript überhaupt, und wo passiert es?

Was ist JavaScript und wozu dient es? L1

HTML baut die Struktur einer Webseite (Überschriften, Absätze, Buttons — das «Was» ist da). CSS gestaltet diese Struktur (Farben, Abstände, Schriften — das «Wie sieht es aus»). Beide sind aber statisch: einmal geladen, passiert von selbst nichts mehr.

JavaScript (JS) ist eine Programmiersprache, die eine Webseite lebendig macht: Sie reagiert auf Klicks, rechnet Werte aus, prüft Formulareingaben, lädt neue Daten nach, ohne dass die Seite neu geladen werden muss. Kurz: HTML = Inhalt, CSS = Aussehen, JS = Verhalten und Interaktion.

SpracheZweckBeispiel
HTMLStruktur / InhaltEin Button existiert auf der Seite
CSSGestaltung / LayoutDer Button ist blau und abgerundet
JavaScriptVerhalten / LogikBeim Klick auf den Button passiert etwas
PrüfungstippWenn gefragt wird «wozu JS im Vergleich zu HTML/CSS»: die Antwort ist immer Interaktivität / Logik / Dynamik, nicht Struktur oder Design.

Fakten über JavaScript L2

  • JavaScript wurde 1995 von Brendan Eich entwickelt (ursprünglich in 10 Tagen, für den Netscape-Browser).
  • Der offizielle Sprachstandard heisst ECMAScript (ES) — «JavaScript» ist die bekannteste Umsetzung davon.
  • JavaScript ist trotz des Namens nicht mit der Programmiersprache Java verwandt. Der Name war ein Marketing-Entscheid der 1990er-Jahre.
  • JavaScript ist eine Skriptsprache: der Code wird nicht vorab kompiliert, sondern direkt vom Browser (bzw. von Node.js) ausgeführt / interpretiert.
  • JavaScript ist dynamisch typisiert: eine Variable hat keinen festen Datentyp und kann im Verlauf des Programms den Typ wechseln.
  • JavaScript ist heute die einzige Programmiersprache, die direkt in jedem Webbrowser läuft — ohne zusätzliche Installation.
  • Neben Webseiten wird JavaScript auch für Server (Node.js), Apps und sogar Desktop-Programme eingesetzt.

Client-Server-Modell: wo läuft JavaScript? L3

Wenn du eine Webseite öffnest, sind mindestens zwei Rechner beteiligt:

Server

Speichert die Webseite (HTML-, CSS-, JS-Dateien) und schickt sie auf Anfrage an deinen Browser. Der Server ist irgendwo im Internet, oft weit weg.

Client

Das ist dein Gerät mit dem Browser (z. B. Chrome, Firefox). Der Browser empfängt die Dateien vom Server und führt JavaScript lokal auf deinem Gerät aus.

// Ablauf, wenn du eine Webseite besuchst: 1. Client (Browser) fordert die Seite beim Server an 2. Server schickt HTML, CSS und JavaScript zurück 3. Browser baut die Seite auf (HTML + CSS) 4. Browser fuehrt das JavaScript lokal aus, direkt bei dir
Merke«Client-seitiges» JavaScript läuft im Browser des Nutzers, nicht auf dem Server. Das ist der Standardfall, den wir in diesem Kurs behandeln. (Node.js wäre der Sonderfall, bei dem JS auf dem Server läuft — das ist hier nicht Thema.)

Verwendete Versionen im Unterricht L4

JavaScript entwickelt sich laufend weiter. Die grösste Zäsur war ES6 (auch ECMAScript 2015 genannt), die moderne Schreibweisen wie let und const einführte. Im Unterricht wird modernes JavaScript (ES6 und neuer) verwendet — das heisst konkret:

  • let und const statt (nur) var für Variablen
  • der strikte Vergleich === wird bevorzugt gegenüber ==
  • Code wird im <script>-Tag oder in einer externen .js-Datei geschrieben
AchtungÄltere Tutorials im Internet nutzen oft noch var und ==. Für diesen Kurs und die Prüfung gilt die moderne Schreibweise mit let/const und ===, ausser var wird explizit verlangt.

LU02 — Erstes JavaScript-Programm

Wie schreibst du die ersten Zeilen Code, wie bindest du sie ein, und wie liest du Fehler?

Text ausgeben: console.log und alert L5

Um zu sehen, was dein Programm tut, brauchst du eine Ausgabe. Es gibt zwei Standardwege:

console.log()

Schreibt Text in die Entwicklerkonsole des Browsers (F12 → Tab «Console»). Für den Nutzer der Seite unsichtbar — nur für dich als Programmierer/in zum Testen und Debuggen.

alert()

Öffnet ein Popup-Fenster im Browser, sichtbar für den Nutzer. Blockiert die Seite, bis das Fenster mit «OK» geschlossen wird.

script.js
console.log("Hallo Welt"); // erscheint in der Konsole alert("Hallo Welt"); // erscheint als Popup fuer den Nutzer
FaustregelZum Testen/Debuggen während der Entwicklung: console.log(). Für eine Meldung, die der Nutzer wirklich sehen soll: alert() — aber sparsam, da es die Seite blockiert.

JavaScript in eine Webseite einbinden L6

Es gibt mehrere Wege, JS mit einer HTML-Seite zu verbinden. Für die Prüfung reichen diese zwei:

1. Intern (im <script>-Tag)

Der JS-Code steht direkt zwischen <script>-Tags in der HTML-Datei.

<script> console.log("Hallo"); </script>

2. Extern (eigene .js-Datei)

Der Code liegt in einer eigenen Datei (z. B. script.js) und wird eingebunden.

<script src="script.js"></script>

Es gibt zusätzlich inline JavaScript direkt in einem HTML-Attribut (z. B. <button onclick="alert('Hi')">) — das erfüllt technisch auch «JS einbinden», gilt aber als schlechter Stil und wird in modernem Code vermieden.

Wo im HTML?Externe Scripts stehen meist am Ende von <body>, damit die Seite zuerst aufgebaut ist, bevor das JS läuft. Mit dem Attribut defer im <head> erreicht man dasselbe.

Einfache Fehlermeldungen analysieren L7

Wenn im Code ein Fehler steckt, bricht JavaScript ab und zeigt in der Konsole eine Fehlermeldung. Sie besteht meist aus drei Teilen: dem Fehlertyp, einer Beschreibung und der Zeilennummer, wo der Fehler auftrat.

FehlertypBedeutetTypisches Beispiel
SyntaxErrorDer Code verstösst gegen die Grammatik von JS (Tippfehler, fehlende Klammer)console.log("Hi" (Klammer fehlt)
ReferenceErrorEine Variable/Funktion wird benutzt, die es (noch) nicht gibtconsole.log(name), obwohl name nie definiert wurde
TypeErrorEine Operation passt nicht zum Datentyplet x = 5; x.push(1); — Zahlen haben kein push
Konsole
Uncaught ReferenceError: alter is not defined at script.js:3

So liest du das: ReferenceError (Typ) — «alter is not defined» (die Variable alter wurde benutzt, aber nie erstellt) — Zeile 3 (dort im Code nachsehen).

Vorgehen bei einer Fehlermeldung1) Fehlertyp lesen. 2) Zeilennummer öffnen. 3) Zeile davor/danach prüfen (oft liegt die eigentliche Ursache eine Zeile vor der gemeldeten). 4) Häufigste Ursachen zuerst ausschliessen: Tippfehler im Namen, fehlende Klammer/Anführungszeichen, Gross-/Kleinschreibung.

LU03 — Variablen und Datentypen in JavaScript

Wie speichert man Werte, und welche Arten von Werten gibt es?

Unterschied zwischen let, var und const L8

Alle drei erstellen eine Variable — sie unterscheiden sich darin, ob der Wert später geändert werden darf und wo im Code sie gültig sind.

SchlüsselwortWert änderbar?GültigkeitsbereichWann verwenden
let✓ jaBlock ({ }, z. B. innerhalb einer Schleife/if)Standard, wenn sich der Wert ändern wird
const✗ neinBlockStandard, wenn der Wert fix bleibt (Empfehlung: immer zuerst const probieren)
var✓ jaganze Funktion (nicht Block) — veraltetNur in altem Code; in neuem Code vermeiden
let alter = 16; alter = 17; // OK, let darf ueberschrieben werden const name = "Alex"; name = "Bea"; // TypeError! const darf nicht neu zugewiesen werden
PrüfungsfalleEine typische Prüfungsaufgabe zeigt Code, der eine const-Variable später überschreibt — das ist ein Fehler und muss als solcher erkannt werden (→ TypeError: Assignment to constant variable).

Werte zuweisen L9

Eine Zuweisung geschieht mit dem Gleichheitszeichen =. Links steht immer der Name der Variable/Konstante, rechts der Wert.

let punkte; // Variable deklarieren, noch ohne Wert (= undefined) punkte = 42; // Wert zuweisen let level = 1; // Deklaration + Zuweisung in einer Zeile (ueblich) level = level + 1; // neuer Wert = alter Wert + 1 -> level ist jetzt 2
Merkeconst muss bei der Deklaration sofort einen Wert bekommen — im Gegensatz zu let, das auch ohne Startwert deklariert werden darf.

Datentypen: String, Number, Boolean, undefined, null L10

TypWas er speichertBeispielWann verwenden
StringText / Zeichenketten, in Anführungszeichen"Hallo", 'Mediamatik'Namen, Texte, Nachrichten
NumberZahlen (ganz und mit Komma, ein einziger Typ für beides)16, 3.5, -2Alter, Preise, Berechnungen
BooleanWahrheitswerttrue, falseJa/Nein-Zustände, Bedingungen
undefinedVariable existiert, hat aber (noch) keinen Wertlet x; → x ist undefinedEntsteht automatisch, wird selten selbst zugewiesen

let name = "Mia"; // String let alter = 16; // Number let istSchueler = true; // Boolean let spitzname; // undefined (noch kein Wert zugewiesen) let zweitname = null; // null (bewusst "kein Wert")
undefined vs. null — der Unterschied, der oft geprüft wirdundefined passiert von selbst (Variable wurde nie gefüllt). null setzt man absichtlich, um «kein Wert» auszudrücken. Beide sind «leer», aber mit anderer Bedeutung.

Vergleichsoperatoren korrekt anwenden L11

OperatorBedeutungBeispielErgebnis

Der klassische AnfängerfehlerEin einzelnes = ist eine Zuweisung, kein Vergleich! if (alter = 18) weist 18 zu (Fehler), statt zu vergleichen. Für Vergleiche immer === (zwei/drei Gleichheitszeichen) verwenden.

Der Operator typeof L12

typeof gibt dir den Datentyp eines Wertes als String zurück — nützlich, um zu prüfen, womit du gerade arbeitest.

typeof "Hallo"; // "string" typeof 16; // "number" typeof true; // "boolean" typeof spitzname; // "undefined" (nie zugewiesen) typeof null; // "object" -- historischer Bug in JS, gilt als bekannte Ausnahme!
Prüfungswissentypeof null ergibt "object", nicht "null". Das ist seit den Anfängen von JavaScript ein bekannter Design-Fehler, der aus Kompatibilitätsgründen nie behoben wurde — als Ausnahme merken.

Syntax- und semantische Fehler selbstständig erkennen L13

Es gibt zwei Fehlerarten, die du unterscheiden können musst:

Syntaktischer Fehler (Aufbau)

Der Code verstösst gegen die Grammatik von JavaScript. Das Programm startet gar nicht erst — sofortiger SyntaxError.

let x = 5 // fehlendes Semikolon -> oft noch ok console.log(x // fehlende schliessende Klammer -> SyntaxError

Semantischer Fehler (Bedeutung)

Der Code ist grammatikalisch korrekt und läuft — liefert aber ein falsches Ergebnis, weil die Logik nicht stimmt.

let summe = 5 - 3; // laeuft fehlerfrei, // aber "summe" sollte wohl 5 + 3 sein
VorgehenBricht der Code sofort ab und die Konsole zeigt einen Fehler → syntaktisch. Der Code läuft durch, aber das Ergebnis stimmt nicht mit der Erwartung überein → semantisch. Semantische Fehler findet man nur, indem man den Code Zeile für Zeile «im Kopf durchspielt» und mit dem erwarteten Ergebnis vergleicht.

LU04 — Programmfluss steuern

Wie lässt du dein Programm Entscheidungen treffen?

Kontrollstrukturen: if...else L14

Mit if...else lässt du das Programm je nach Bedingung unterschiedlichen Code ausführen. Die Bedingung in ( ) muss zu true oder false auswertbar sein.

let alter = 16; if (alter >= 18) { console.log("volljaehrig"); } else { console.log("minderjaehrig"); // dieser Zweig laeuft }

Aufbau (Syntax): if (Bedingung) { Anweisungen } else { Anweisungen }. Die geschweiften Klammern { } markieren, welcher Code zu welchem Zweig gehört. Der else-Teil ist optional.

if-else mit logischen Operatoren L15

OperatorBedeutungBeispiel
&&UND — beide Bedingungen müssen wahr seinalter >= 16 && hatAusweis
||ODER — mindestens eine Bedingung muss wahr seinistFeiertag || istWochenende
!NICHT — kehrt den Wahrheitswert um!istGesperrt
let alter = 17; let hatErlaubnis = true; if (alter >= 16 && hatErlaubnis) { console.log("Eintritt erlaubt"); // laeuft, da BEIDE Bedingungen wahr sind } else { console.log("kein Eintritt"); }
Falle&& ist strenger als ||: bei && reicht eine falsche Bedingung, damit das ganze Ergebnis false ist. Bei || reicht eine wahre Bedingung für ein true-Ergebnis.

if-else mit Verschachtelungen L16

Eine if-Struktur kann eine weitere if-Struktur enthalten — das nennt man Verschachtelung. Damit lassen sich mehrere Stufen von Entscheidungen abbilden. Häufig praktischer: else if, um mehrere Fälle nacheinander zu prüfen.

let note = 5.2; if (note >= 5.5) { console.log("sehr gut"); } else if (note >= 4.5) { console.log("genuegend"); // laeuft: 5.2 >= 4.5, aber < 5.5 } else { console.log("nicht genuegend"); }

Echte Verschachtelung (ein if im if):

if (istEingeloggt) { if (istAdmin) { console.log("Admin-Bereich"); } else { console.log("Nutzer-Bereich"); } } else { console.log("bitte einloggen"); }
Wann verschachteln, wann else if?Prüfst du eine Grösse gegen mehrere Bereiche (z. B. Notenskala) → else if-Kette. Hängt die zweite Bedingung von der ersten ab (erst wenn eingeloggt, dann Rolle prüfen) → Verschachtelung.

switch-case L17

switch vergleicht einen Wert mit mehreren möglichen Fällen — praktisch, wenn eine einzelne Variable viele feste Werte annehmen kann (Alternative zu einer langen else if-Kette).

let tag = "Mittwoch"; switch (tag) { case "Montag": console.log("Wochenstart"); break; case "Mittwoch": console.log("Wochenmitte"); // dieser Fall trifft zu break; case "Freitag": console.log("fast Wochenende"); break; default: console.log("normaler Tag"); }

Aufbau: switch (Wert) { case Möglichkeit1: ...; break; case Möglichkeit2: ...; break; default: ... }. default greift, wenn kein case passt (wie ein else).

Die wichtigste switch-Falle: break vergessenOhne break läuft das Programm in den nächsten case weiter («Fallthrough»), auch wenn dieser eigentlich nicht zutrifft. Jeder case-Block braucht (fast immer) ein eigenes break.

LU05a — Arrays in JavaScript

Wie speicherst du mehrere Werte zusammen in einer Variable?

Was ist ein Array, und wozu dient es? L18

Ein Array ist eine geordnete Liste von Werten, gespeichert unter einem einzigen Namen. Statt für jeden Schüler eine eigene Variable zu erstellen (schueler1, schueler2, …), speicherst du sie alle in einem Array: schueler. Jeder Wert im Array hat eine feste Position, den Index, beginnend bei 0.

const namen = ["Mia", "Leon", "Sara"]; // Index 0 Index 1 Index 2
MerkeEin Array wird meist mit const deklariert — nicht weil sich der Inhalt nicht ändern darf (Elemente hinzufügen/entfernen ist erlaubt!), sondern weil sich der Name nicht auf ein anderes Array umbiegen soll.

Arrays mit verschiedenen Datentypen erzeugen L19

Ein Array kann Werte von beliebigen Datentypen enthalten — sogar gemischt.

const zahlen = [4, 8, 15, 16]; // nur Numbers const namen = ["Mia", "Leon"]; // nur Strings const flags = [true, false, true]; // nur Booleans const gemischt = ["Mia", 16, true, null]; // gemischte Typen -- erlaubt const leer = []; // leeres Array, 0 Elemente

Elemente per Index lesen, hinzufügen, entfernen L20

const obst = ["Apfel", "Birne", "Kiwi"]; console.log(obst[0]); // "Apfel" -- erstes Element, Index 0 console.log(obst[2]); // "Kiwi" -- drittes Element, Index 2 obst[1] = "Traube"; // Element an Index 1 ueberschreiben ("Birne" -> "Traube") // Einfuegen an einer bestimmten Stelle: splice(startIndex, anzahlZuLoeschen, neuesElement) obst.splice(1, 0, "Mango"); // fuegt "Mango" an Index 1 ein, loescht nichts // Entfernen an einer bestimmten Stelle: obst.splice(0, 1); // loescht 1 Element ab Index 0
Häufiger FehlerDer Index des letzten Elements ist nicht die Länge des Arrays, sondern length - 1. Ein Array mit 3 Elementen hat die Indizes 0, 1, 2 — obst[3] existiert nicht und ergibt undefined.

Die Länge eines Arrays mit length ermitteln L21

const farben = ["rot", "gruen", "blau"]; console.log(farben.length); // 3 // Praktisch: letztes Element ueber length ansprechen console.log(farben[farben.length - 1]); // "blau"

Die Array-Methoden push und pop L22

push()

Fügt ein oder mehrere Elemente am Ende des Arrays hinzu. Gibt die neue Länge zurück.

const liste = ["a", "b"]; liste.push("c"); // liste ist jetzt ["a", "b", "c"]

pop()

Entfernt das letzte Element des Arrays und gibt genau dieses Element zurück.

const liste = ["a", "b", "c"]; const entfernt = liste.pop(); // entfernt = "c", liste ist jetzt ["a", "b"]
Merkhilfepush = «hinten reinschieben», pop = «hinten rausnehmen». Beide arbeiten nur am Ende des Arrays.

LU05b — Schleifen (Loops)

Wie wiederholst du Code, ohne ihn mehrfach abzutippen?

Unterschied zwischen for und while L23

Beide wiederholen einen Codeblock, solange eine Bedingung wahr ist — der Unterschied liegt darin, wie klar von Anfang an feststeht, wie oft wiederholt wird.

forwhile
EinsatzAnzahl Durchläufe ist im Voraus bekanntAnzahl Durchläufe hängt von einer Bedingung ab, die sich zur Laufzeit ändert
AufbauStart, Bedingung, Schritt in einer Zeilenur die Bedingung; Start und Schritt stehen ausserhalb/im Block
Beispiel«Zähle von 1 bis 10»«Wiederhole, bis der Nutzer das richtige Passwort eingibt»

Schleifen korrekt anwenden/programmieren L24

for-Schleife — Aufbau

for (let i = 0; i < 5; i++) { console.log(i); // gibt 0, 1, 2, 3, 4 aus } // Start: let i = 0 (Zaehler bei 0 beginnen) // Bedingung: i < 5 (weitermachen, solange i kleiner als 5 ist) // Schritt: i++ (nach jedem Durchlauf i um 1 erhoehen)

Typischer Einsatz: alle Elemente eines Arrays durchgehen.

const namen = ["Mia", "Leon", "Sara"]; for (let i = 0; i < namen.length; i++) { console.log(namen[i]); } // Ausgabe: Mia / Leon / Sara

while-Schleife — Aufbau

let i = 0; // Start: ausserhalb der Schleife while (i < 5) { // Bedingung console.log(i); i++; // Schritt: muss im Block selbst passieren! }
Endlosschleife — der gefährlichste FehlerVergisst man bei while den Schritt (i++), bleibt die Bedingung für immer wahr, und das Programm hängt sich auf. Bei for passiert das seltener, weil Start/Bedingung/Schritt direkt sichtbar zusammenstehen.

a → "string" (Anführungszeichen) · b → "number" · c → "boolean" · d → "undefined" (nie zugewiesen) · e → "object" (Sonderfall von null).

Ü7 — eigene Beispiele bauen

Schreibe für jeden Datentyp (String, Number, Boolean, undefined, null) eine eigene, sinnvolle Variable aus dem Alltag einer Mediamatikerin/eines Mediamatikers (z. B. für eine Kundendatenbank).

Lösung anzeigen

Konzept: Anwendung der Datentypen auf einen realistischen Kontext — es gibt keine einzige richtige Lösung, wichtig ist die korrekte Zuordnung.

Beispiel:

let kundenname = "Sara Meier"; // String let rechnungsbetrag = 249.90; // Number let hatBezahlt = false; // Boolean let telefonnummer; // undefined, noch nicht erfasst let zweiteAdresse = null; // null, bewusst: es gibt keine zweite Adresse

Ü8 — Vergleichsoperatoren

Level 2L11

Was geben diese Ausdrücke zurück?

7 === "7" 7 == "7" 7 !== 8 3 >= 3
Lösung anzeigen

Konzept: strikter vs. loser Vergleich.

7 === "7" → false (unterschiedlicher Typ) · 7 == "7" → true (Typ wird ignoriert) · 7 !== 8 → true · 3 >= 3 → true.

Schreibe ein Programm, das prüft, ob eine Zahl zahl gerade oder ungerade ist (Tipp: der Restwert-Operator % gibt den Rest einer Division zurück, z. B. 10 % 2 ergibt 0).

Lösung anzeigen

Konzept: Bedingung mit Restwert-Operator formulieren.

let zahl = 7; if (zahl % 2 === 0) { console.log("gerade"); } else { console.log("ungerade"); // laeuft: 7 % 2 = 1, nicht 0 }

Ü10 — logische Operatoren kombinieren

Level 3L15

Ein Lernpaket ist gratis, wenn der Nutzer entweder Student ist oder mindestens 5 Kurse gekauft hat. Schreibe die passende Bedingung.

Lösung anzeigen

Konzept: Wahl zwischen && und || — «entweder … oder» = ODER, keine Kombinationspflicht.

let istStudent = false; let gekaufteKurse = 6; if (istStudent || gekaufteKurse >= 5) { console.log("Paket ist gratis"); // laeuft, da gekaufteKurse >= 5 }

Ü11 — verschachtelte Bedingungen

Level 3L16

Schreibe ein Programm: Ist istMitglied falsch, gib «kein Zugang» aus. Ist istMitglied wahr, prüfe zusätzlich, ob alter >= 16 ist: falls ja, gib «voller Zugang» aus, sonst «eingeschränkter Zugang».

Lösung anzeigen

Konzept: zweite Bedingung ist nur relevant, wenn die erste zutrifft → Verschachtelung, nicht else if.

let istMitglied = true; let alter = 15; if (istMitglied) { if (alter >= 16) { console.log("voller Zugang"); } else { console.log("eingeschraenkter Zugang"); // laeuft } } else { console.log("kein Zugang"); }

Ü12 — switch-case bauen

Schreibe ein switch, das je nach Variable note ("A", "B", "C") eine passende Meldung ausgibt, und für alle anderen Werte «unbekannte Note».

Lösung anzeigen

Konzept: switch-Syntax mit default-Fall.

let note = "B"; switch (note) { case "A": console.log("ausgezeichnet"); break; case "B": console.log("gut"); // laeuft break; case "C": console.log("genuegend"); break; default: console.log("unbekannte Note"); }

Ü13 — switch-Fehler finden

Level 3L17, L13

Was gibt dieser Code aus, wenn tag = "Montag"? Erkläre, warum.

switch (tag) { case "Montag": console.log("Start"); case "Dienstag": console.log("Fortsetzung"); break; default: console.log("Sonst"); }
Lösung anzeigen

Konzept: Fallthrough durch fehlendes break.

Ausgabe: "Start" und "Fortsetzung". Nach dem passenden case "Montag" fehlt das break, daher läuft der Code in den nächsten case weiter, bis ein break kommt.

Ü15 — push, pop, length kombinieren

Level 2L20, L21, L22

Ein Array warenkorb enthält ["Buch", "Stift"]. Füge "Heft" hinzu, entferne danach das letzte Element wieder, und gib am Ende die Länge des Arrays aus.

Lösung anzeigen

Konzept: Zusammenspiel von push, pop und length.

const warenkorb = ["Buch", "Stift"]; warenkorb.push("Heft"); // ["Buch", "Stift", "Heft"] warenkorb.pop(); // entfernt "Heft" -> ["Buch", "Stift"] console.log(warenkorb.length); // 2

Ü16 — Array-Fehler finden

Level 3L20, L13

Ein Array liste hat 4 Elemente. Jemand schreibt liste[4], um das letzte Element zu lesen. Was passiert, und wie muss es richtig heissen?

Lösung anzeigen

Konzept: Indexierung beginnt bei 0 — häufigster Array-Fehler.

Bei 4 Elementen sind die gültigen Indizes 0–3. liste[4] existiert nicht und ergibt undefined — kein Absturz, aber ein semantischer Fehler. Richtig: liste[3] oder besser liste[liste.length - 1].

Ü18 — while-Schleife anwenden

Ü19 — Schleifenfehler finden (Endlosschleife)

Level 3L23, L24, L13

Dieser Code hängt sich beim Ausführen auf. Finde den Fehler.

let i = 0; while (i < 5) { console.log(i); }
Lösung anzeigen

Konzept: Endlosschleife durch fehlenden Schritt erkennen.

i wird im Schleifenkörper nie verändert, die Bedingung i < 5 bleibt also für immer wahr. Fix: i++; am Ende des Blocks ergänzen.

Ü20 — Transferaufgabe: for oder while wählen

Level 4L23

Begründe für jede Situation, ob eher for oder while passt: a) alle 30 Fragen eines Quiz durchgehen, b) so lange raten, bis die richtige Zahl getroffen wurde.

Lösung anzeigen

Konzept: Transfer — Wahl der passenden Schleifenart begründen, nicht nur anwenden.

a) for, weil die Anzahl (30) von Anfang an feststeht. b) while, weil im Voraus nicht bekannt ist, wie viele Versuche nötig sind — die Wiederholung hängt von einer Bedingung ab, die sich erst während der Ausführung entscheidet.

Ü21 — Kombinierte Transferaufgabe

const eintritte = [16, 15, 19, 12, 20]; let anzahlErlaubt = 0; for (let i = 0; i < eintritte.length; i++) { if (eintritte[i] >= 16) { anzahlErlaubt = anzahlErlaubt + 1; } } console.log(anzahlErlaubt); // 3 (16, 19, 20 erfuellen die Bedingung)

Aufgabe 1 (8 Punkte) — Fehler finden und korrigieren

Prüfung

Der folgende Code soll prüfen, ob ein Kunde ein Treuerabatt-Set (mind. 3 Käufe UND Mitglied) erhält, tut das aber nicht korrekt. Finde alle Fehler (es sind 3) und schreibe den korrigierten Code auf.

const kaeufe = 3; let istMitglied = true if (kaeufe >= 3 || istMitglied = false) { console.log("Rabatt erhalten"); } else console.log("kein Rabatt"); }
Musterlösung anzeigen

Fehler 1: fehlendes Semikolon nach let istMitglied = true (schlechter Stil, in diesem Fall aber nicht fatal — sauberer Code ergänzt es).

Fehler 2 (inhaltlich am wichtigsten): istMitglied = false ist eine Zuweisung (ein =), kein Vergleich, und die Bedingung soll ausserdem && statt || sein, weil laut Aufgabe beide Bedingungen gelten müssen. Richtig: kaeufe >= 3 && istMitglied === true (oder kurz istMitglied).

Fehler 3: Die schliessende geschweifte Klammer des if-Blocks fehlt vor dem else. Korrigierter Code:

const kaeufe = 3; let istMitglied = true; if (kaeufe >= 3 && istMitglied) { console.log("Rabatt erhalten"); } else { console.log("kein Rabatt"); }

Aufgabe 2 (6 Punkte) — Array mit Schleife auswerten

Prüfung

Gegeben ist das Array preise = [12, 45, 8, 30, 5]. Schreibe ein vollständiges JavaScript-Programm, das a) die Summe aller Preise berechnet und ausgibt, und b) zählt, wie viele Preise unter 10 liegen.

Musterlösung anzeigen
const preise = [12, 45, 8, 30, 5]; let summe = 0; let anzahlGuenstig = 0; for (let i = 0; i < preise.length; i++) { summe = summe + preise[i]; if (preise[i] < 10) { anzahlGuenstig = anzahlGuenstig + 1; } } console.log("Summe: " + summe); // 100 console.log("unter 10: " + anzahlGuenstig); // 2 (8 und 5)

Bewertung: je 1 Punkt für korrekte Deklaration der Variablen, 2 Punkte für die Schleife, 2 Punkte für die Summenberechnung, 1 Punkt für den korrekten Zähler-Vergleich.
